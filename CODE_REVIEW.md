## 🔴 Критичные баги

### 1. `EnsureRoot()` — двойное выполнение команды (`process/process.go`)

Поток выполнения:

- не-root запускает `sudo exe ...` как **дочерний процесс** и ждёт его (`cmd.Run()` блокирует);
- ребёнок работает под root: печатает таблицу / убивает процессы;
- `cmd.Run()` вернулся → `EnsureRoot` вернул `nil` → **родитель продолжает выполнение** и делает ту же работу **ещё раз уже без прав**.

Симптомы:
- при `list` вывод дублируется (root-копия + неполный non-root вывод);
- при `kill` — двойной проход по списку.

**Фикс:** после успешного перезапуска родитель должен завершаться, пробрасывая exit code ребёнка. Подсказка: `cmd.Run()` возвращает `*exec.ExitError`, из которой можно достать код выхода.

### 2. Проглоченная ошибка в `runList` (`cli/cli.go`)

Ветка «list без флагов»: `commands.ListAll()` вызывается как statement, а `ListAll` возвращает `error` из `Collect`.

Сейчас: если `Collect` упал — пользователь увидит пустоту и `exit 0`. Все соседние ветки возвращают ошибку, эта — нет.

### 3. Версия в релизах всегда `dev`

В `.goreleaser.yaml` флаг `-X` использует путь:

```
-X portkiller/internal/version.Version={{.Version}}
```

но реальный путь — `github.com/Awak3r/PortKiller/internal/version`. Неправильный путь линкер **молча игнорирует**.

Плюс `Commit` и `Date` — переменных с такими именами в `internal/version/version.go` вообще нет.

**Проверка:** собрать бинарник goreleaser'ом и глянуть `--version`.

## 🟠 Серьёзные проблемы

### 4. Три разные семантики поиска имени — самый коварный пункт

| Где | Семантика | Пример |
|---|---|---|
| `list` | `strings.HasPrefix` (префикс) | `list -name ngin` найдёт nginx |
| `kill` | `strings.EqualFold` (точное совпадение) | `kill -name ngin` скажет «не найдено» |
| README | обещает **substrings** | — |

Для утилиты, которая **убивает процессы**, расхождение между «что видел в list» и «что матчит kill» — путь к тому, что юзер убьёт не то или не убьёт то, что хотел.

**Фикс:** унифицировать семантику и задокументировать.

### 5. sudo спрашивается слишком рано и слишком часто

- `EnsureRoot` вызывается и для `list` — юзер вводит пароль ради просмотра;
- порядок в `runList`/`runKill`: сначала sudo-промпт, потом валидация порта. Невалидный порт = ввёл пароль и получил «invalid port».

**Фикс:** правильный порядок — парсинг → валидация → эскалация → выполнение.

### 6. Потеря статистики при частичном kill

`KillByName` возвращает `found=3, killed=2` и joined-ошибку. Но в `runKill` печать `found/killed` стоит в ветке `err == nil` — при частичном успехе юзер не узнает, сколько убилось.

## 🟡 Рефакторинг / качество

### 7. Копипаста

- валидация порта повторена **4 раза**;
- фильтрация: 4 варианта в `list.go` + 3 почти идентичных тела в `kill.go`.

**Фикс:** один предикат-фильтр `(name, port)` сводит обе команды к одной функции каждая.

### 8. Тестируемость

`cli_test.go` это уже показывает — кейсы «list без флагов» скипаются, потому что библиотечный код дёргает sudo и не даёт себя протестировать.

**Направление:** эскалация — в `main` (там `os.Exit` законен), в `cli` — интерфейсы-заглушки для `Collect`/`Kill`. Тогда скипы уйдут.

### 9. Мелочи

- `func EnsureRoot() error{` — нет пробела (`gofmt -l .` это покажет);
- `Terminate` = SIGTERM: зависший процесс не умрёт — нет SIGKILL-fallback;
- README говорит «Cross-platform», а `.goreleaser.yaml` собирает только linux; к тому же на Windows пути `sudo` нет.
