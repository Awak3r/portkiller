# PortKiller 🔪

Небольшая CLI-утилита, чтобы увидеть, какие процессы занимают TCP-порты, и завершить их — по порту, по имени или по обоим сразу. Один статический бинарник без рантайм-зависимостей.

Собрана на [cobra](https://github.com/spf13/cobra) и [gopsutil](https://github.com/shirou/gopsutil).

## Возможности

- 📋 `list` — таблица процессов, слушающих TCP-порты (работает **без** root)
- 💀 `kill` — завершение процессов по порту, по имени или по имени + порту (просит root)
- 🔍 Матчинг имени: **подстрока** без учёта регистра — семантика одна для `list` и `kill`: что видно в `list`, то и убьёт `kill`
- 🪜 Двухступенчатое завершение: сначала SIGTERM, для игнорирующих — фолбэк SIGKILL (см. [Как работает убийство](#как-работает-убийство))
- 📊 Отчёт об убийствах даже при частичном успехе: `found N process(es), killed M`
- ⚡ Эскалация только когда нужна: `list` никогда не спрашивает пароль, а `kill` валидирует флаги **до** запроса пароля

## Установка

### Способ 1: через Go

Требуется **Go 1.26+** (см. `go.mod`):

```bash
go install github.com/Awak3r/PortKiller/cmd/portkiller@latest
```

Убедись, что `$(go env GOPATH)/bin` есть в `PATH` (разовая настройка):

```bash
echo 'export PATH=$PATH:$(go env GOPATH)/bin' >> ~/.zshrc   # или ~/.bashrc
source ~/.zshrc
```

### Способ 2: готовые бинарники

Забери архив на [Releases](https://github.com/Awak3r/PortKiller/releases) — сейчас собираются Linux-архивы `portkiller_<версия>_linux_<арх>.tar.gz` для `amd64` / `arm64`. Распакуй и положи в директорию из `PATH`:

```bash
tar -xzf portkiller_2.0.0_linux_amd64.tar.gz
sudo mv portkiller /usr/local/bin/
```

> Релизы собирает GoReleaser по пушу тега (`v*`), версия/коммит/дата вшиваются через `-ldflags`.

### Способ 3: сборка из исходников

```bash
git clone https://github.com/Awak3r/PortKiller.git
cd PortKiller
go build -o portkiller ./cmd/portkiller
```

## Использование

```text
portkiller — kill processes by name or port

Usage:
  portkiller [command]

Available Commands:
  list   List processes
  kill   Kill processes by name and/or port

Flags:
  -h, --help      help for portkiller
  -v, --version   version for portkiller
```

Бинарник называется `portkiller`. Команды принимают длинные флаги в GNU-стиле (`--port`, `--name`) с однобуквенными алиасами (`-p`, `-n`); парсер принимает и форму с одним тире, и с двумя.

### Список занятых портов (без root)

```bash
portkiller list
```

```text
PROCESS     PORT   PID
-------     ----   ----
node        3000   12345
postgres    5432   999
```

Фильтрация — как у `kill`:

```bash
portkiller list --name node        # по имени (подстрока, без учёта регистра)
portkiller list --port 3000        # по порту
portkiller list --name node --port 3000
```

### Убийство по порту

```bash
sudo portkiller kill --port 5000
```

### Убийство по имени

```bash
sudo portkiller kill --name node
```

Матчится каждый процесс, в имени которого есть `node` (без учёта регистра) — `node`, `NODE`, `my-node-app`.

Не уверен? Сначала посмотри — без root и без убийства:

```bash
portkiller kill --dry-run --name node
```

### Убийство по имени и порту

```bash
sudo portkiller kill --name node --port 3000
```

Оба условия должны совпасть одновременно.

### Коды выхода

| Код | Значение |
|-----|----------|
| `0` | Успех |
| `1` | Некорректный вызов, ничего не найдено или процессы не удалось убить |

## Флаги

| Флаг (длинный / короткий) | Применяется к | Описание |
|---------------------------|---------------|----------|
| `--port` / `-p`           | `list`, `kill` | TCP-порт, целое число 1–65535 |
| `--name` / `-n`           | `list`, `kill` | Имя процесса, подстрока без учёта регистра |
| `--dry-run`               | `kill`        | Показать, что будет убито (та же таблица, что у `list`), без убийства и без sudo |
| `--help` / `-h`           | везде | Справка |
| `--version` / `-v`        | корневая команда | Версия: `portkiller version X (commit Y, built Z)` |

Валидация: невалидный порт (`portkiller kill --port 70000`) завершается ошибкой **сразу, до sudo-промпта**; `kill` без флагов печатает `kill requires -name or -port`.

## Root и права

- **`list` не требует root.** Чтение таблицы TCP доступно любому пользователю (детали чужих процессов могут быть видны не полностью, но порты и PID показываются).
- **`kill` требует root**, чтобы отправлять сигналы чужим процессам. Если запустить `portkiller kill ...` от обычного пользователя:
  1. сначала валидируются флаги (невалидный порт → ошибка, пароль не спрашивается);
  2. утилита перезапускает саму себя через `sudo` (по текущему пути бинарника —
     держи его в каталоге, принадлежащем root, например `/usr/local/bin`), и спрашивает пароль; без подключённого терминала она завершится понятным сообщением вместо маловразумительной ошибки sudo;
  3. exit code ребёнка пробрасывается наружу — скрипты могут на него полагаться.
- Можно и сразу под root/sudo: `sudo portkiller kill --name nginx`.

## Как работает убийство

Завершение — **двухступенчатая эскалация** (реализовано в `internal/port.KillByPid`):

**Ступень 1 — SIGTERM.** Процесс получает «вежливую» просьбу завершиться. Корректная программа может перехватить сигнал и закрыться аккуратно: закрыть сокеты, сбросить буферы, удалить pidfile, сохранить состояние.

**Grace period.** PortKiller ждёт до **2 секунд** (опрос каждые 100 мс), не завершился ли процесс.

**Ступень 2 — фолбэк SIGKILL.** Если процесс всё ещё жив после grace period (завис, застрял в I/O или явно игнорирует/перехватывает SIGTERM), PortKiller отправляет **SIGKILL**. Этот сигнал нельзя перехватить, заблокировать или проигнорировать — ядро уничтожает процесс немедленно, без какой-либо очистки. Именно фолбэк гарантирует, что зависший процесс всё равно умрёт.

Зачем тогда ступень 1? Потому что SIGKILL лишает процесс шанса прибраться за собой — в большинстве случаев SIGTERM достаточен и является безопасным выбором; SIGKILL — крайняя мера. Конкретные сценарии:

| Сценарий | Что происходит |
|----------|----------------|
| Обычное приложение (nginx, node, postgres) | Умирает от SIGTERM, обычно за миллисекунды |
| Приложение перехватило SIGTERM и игнорирует его | Получает SIGKILL после 2 секунд grace period |
| Процесс исчез между списком и сигналом (`ESRCH`) | Не ошибка — цель уже достигнута |
| Сам `SIGKILL` не сработал (например, edge case с переиспользованием PID) | Возвращается как ошибка, попадает в итоговый отчёт |

Результат по каждому процессу агрегируется: даже если часть убийств не удалась, ты всё равно получишь `found N process(es), killed M` плюс собранные ошибки, а exit code будет ненулевым.

## Статус кроссплатформенности

Логика `list`/`kill` кроссплатформенная благодаря gopsutil, но **сейчас пайплайн релизов собирает только Linux-бинарники** (`amd64`, `arm64`), а эскалация прав использует `sudo` — это POSIX-конвенция (на Windows понадобился бы другой механизм). Смотри `.goreleaser.yaml` — добавление таргетов `darwin`/`windows` в планах.
